The best family: RecurrenceNet + a window-level side path

Trunk (RecurrenceNet, ~25k parameters)

  • Encoder: a per-sample linear map C → 32.
  • 3 recurrence blocks, each: LayerNorm; u = Win·x (32); z = Wemb·x, 8 points in 2-D.
  • Soft recurrence at 10 lags τ ∈ {1, 2, 4, 6, 8, 12, 16, 24, 32, 48}: r(t, τ) = σ((ε − ‖zt − zt−τ‖) / 0.1), a learned radius ε per point, 0 before t = τ.
  • Diagonal-line feature r(t, τ)·r(t−1, τ) (a recurrence that lasts two steps); mixing 192 → 32, GELU, residual.
  • Mean over time. Causal: every output at t uses samples up to t only, so it can run sample by sample.

Side paths, fused at the head (concat → LayerNorm → linear)

  • Laws (RN + laws, +2.9k): per 3-axis sensor, closed-form ridge fits of lagged operators Aτ (τ = 1, 2, 4, 8, 16) read only through their characteristic polynomial (trace, e2, det: invariant under any rotation of the sensor), the covariance shape, and signed-lag canonical correlations between sensors; asinh, BatchNorm, a small shared MLP.
  • Statistics (RN + statistics, +1.8k): per-channel mean, std, min, max of the window → BatchNorm → linear 32.
  • Cost per 3-s window (UCI-HAR, 9 × 150): 3.5 M multiply-accumulates for the trunk; the law solves add ~50k.

Rounds 1-3 · one dataset (UTD-MHAD), a new memory cell inside one shared skeleton

Edge-SSM v2

stopped

memory cell · 33.6k params

Every connection gets its own leaky memory with a learnable time constant and its own learned function (KAN-like).

UTD-MHAD 51.6 against S4D 73.8; the time constants do not learn.

Novelty: the original idea

HysteresisNet (selective + clock)

kept

memory cell · 23.6k params

Play operators clamp(y, u − r, u + r) with input-dependent width r and a clock channel: memory that ignores the sampling rate.

3-seed mean 70.69 over 10 datasets (S4D 71.29). Rate-independent, but S4D matches it once given a standard resampling pipeline.

Novelty: partly new (Preisach-relay layers in theory only, 2026)

Part III · On the microcontrollers

NUCLEO-L4R5ZI (Cortex-M4F, 120 MHz, 640 KB SRAM, 2 MB Flash)

UCI-HAR windows (9 channels × 150 samples at 50 Hz), split 0. Latency = median DWT time per window; Flash/RAM = the model's own objects in the linker map. Why the kernel needs so little memory

  • RAM 21 KB against 192 KB (RN + laws INT8): the generated graph holds window-sized intermediate tensors (102 KB) and a descriptor per node and tensor (89 KB); the kernel keeps per block a 32-value state and the last 49 embeddings (9.4 KB for 3 blocks, independent of the window length), plus the stored window for the law solves.
  • Flash 45 KB against 343 KB: one set of loops reused for every block and step instead of generated code per node (224 KB), layer-name strings (33 KB) and the runtime library (35 KB).

What set the speed

  • Plain loops 360 ms → weights in 8-row blocks 320 → no FMA (3-cycle VFMA on the M4) + VSQRT, short exp/erf → 269 (Flash) / 204 (SRAM) → compact loops (the I-cache is 1 KB) 195 (SRAM); INT8 with SMLAD 206 (Flash) / 183 (SRAM).
  • ST Edge AI: float 1×1 convolutions at 12–17 cycles/MAC; INT8 convolutions ~5, but int8↔float conversions around the float elementwise work cost 150–300 cycles per element.

NUCLEO-N657X0-Q (Cortex-M55 800 MHz + Neural-ART NPU 1 GHz)

ST's own flow (stedgeai --st-neural-art, n6_loader, NPU_Validation, on-board validation). ST's MNIST sample runs in 0.168 ms (78 % on the NPU), so the flow works on this board. For HAR graphs the compiler is the problem:

  • Its software epochs computed a reduction over channels with a broadcast wrongly (encoder + LayerNorm: L2-relative error 7) and Slice / Concat along time wrongly (a delayed copy: 2.5); Pad does not compile; LSTM/GRU models do not compile.
  • N6 export forms (norms as 1/D convolutions, delays as depthwise convolutions, no slices or broadcasts) fixed the first two sub-graphs on the board but not the full recurrence blocks: our models still disagree with the reference.

Part IV · What drives the results

Data, model and evaluation factors

Effects in macro-F1 points on people the model never saw. Temporal memory +5.9 [+2.8, +9.1] (10/10 datasets); laws on RecurrenceNet +2.4 (8/10); the test person 61 % of within-dataset variance against 6 % for the model.

Part V · Findings

What the results support

Grades: strong confirmed or significant after correction; moderate consistent but not formally shown; negative a hypothesis that failed.

Accuracy

  1. strongRN + laws beats S4D on 8 untouched datasets. Pre-registered held-out test: +4.75 [+1.85, +7.65], 8/8 datasets, Wilcoxon p 0.008. Also on the 10 development datasets (+3.12, Holm p 0.049).
  2. strongThe window-level law path generalizes. RN + laws − RecurrenceNet on the held-out datasets: +3.15 [+1.00, +5.30], 8/8 datasets, Wilcoxon p 0.008; +2.4 on the development datasets.
  3. moderateLevel with the best published HAR networks at about a tenth of their size. Held-out, seed 0, RN + laws minus TinyHAR -0.02 [-3.67, +3.63], 4/8 datasets, Wilcoxon p 0.844; minus CNN-HAR +0.76 [-1.57, +3.08], 5/8 datasets, Wilcoxon p 0.742; minus Triple-Cross-Attn +0.49 [-2.72, +3.70], 4/8 datasets, Wilcoxon p 0.844. Point estimates within ±1 point, but formal non-inferiority (margin 1) is not shown with 8 datasets. 29.5k parameters against 296k (TinyHAR).
  4. strongHaving a temporal memory matters; which memory matters little. Memory vs none +5.95 [2.79, 9.10] over 10 datasets; between memory types 1-2 points (Mamba below S4D on 9/10).
  5. negativeNew memory cells do not beat S4D. Quantile, hysteresis, rainflow, ordinal, return-map, ecological, grammar and holonomy memories all land between the memoryless control and RecurrenceNet (rounds 1-10).

Analysis

  1. strongWho is tested matters far more than the architecture. Within a dataset the test person explains 61 % of the variance of 2,460 runs, the training seed 14 %, the model 6 %.
  2. moderateMany channels favour classical models. Over the paper's 30 datasets the Random Forest's margin over the best deep model grows with the channel count (+7.2 points per SD, p < 0.001); few training subjects make the model choice matter more (p 0.005).
  3. moderateSimple segment statistics with trees tie the deep trunks. Segment statistics + ExtraTrees ≈ RecurrenceNet / S4D over 8 datasets, but its size rules it out on a microcontroller.
  4. negativeSampling-schedule robustness needs fair baselines. HysteresisNet's rate independence disappears once S4D gets interpolation or Δ-rescaling (§5k).

Deployment

  1. strongThe causal trunk runs sample by sample in kilobytes. Hand-written C on a Cortex-M4F at 120 MHz: 206-211 ms per 3-s window in INT8, 1.37 ms per sample (6.8 % CPU at 50 Hz), 11-21 KB RAM, 33-45 KB Flash; predictions match PyTorch (F1 −0.02 to −0.03 in INT8 over 10 splits).
  2. strongSame compiler, our models are the fastest deployable ones. ST Edge AI 4.0 INT8 on the L4R5: ours 420-433 ms and 180-192 KB RAM; TinyHAR 494 ms / 216 KB, CNN-HAR 779 / 265, Triple-Cross-Attn 900 / 471, S4D 556 / 145.
  3. strongMost published HAR networks do not deploy faithfully out of the box. Of the paper's 14 deep models, 3 run correctly on the L4R5 through ST Edge AI 4.0 (CNN-HAR only after an export fix); the others do not compile, export or fit. On the N6 the Neural-ART compiler computed reductions with broadcasts and time-axis slices wrongly: on-board validation is not optional.
  4. moderateMCU latency is set by the implementation, not the parameter count. The same RecurrenceNet: 206 ms (C, INT8), 420 ms (ST Edge AI INT8), 648 ms (ST Edge AI FP32). Generated float kernels ran at 12-17 cycles per MAC; int8↔float conversions cost 150-300 cycles per element.

Part VI · Papers

How the results split into papers

Three papers with distinct claims, so none repeats another's main result. Order: P1 first (it is the citable anchor); P2 and P3 can follow in parallel and cite P1 as under review.

P1

IEEE Sensors Journal (full paper) · ready to write

Recurrence-plot layers with invariant window laws for lightweight wearable activity recognition: person-disjoint evaluation on 18 datasets and microcontroller deployment

Claim
A small causal network (RecurrenceNet trunk + per-sensor GL(3)-invariant law path, ~30k parameters) beats a state-space baseline on 8 untouched datasets (pre-registered) and is level with the strongest published HAR networks at a tenth of their size; it runs on a Cortex-M4 microcontroller.
Evidence in hand
Method + best_family figure; dev table vs 17 models; held-out table and tests; accuracy Pareto (dev, held-out); ablations (memory, laws, statistics, random groups); short MCU table (our model, ST Edge AI vs C kernel; RAM/Flash).
Still missing
manuscript in IEEEtran; print-ready figures; check page limits and overlength charges in the current author guidelines; optionally a second MCU input shape. Energy stays an estimate from the datasheet (no power meter available): say so.
Risks
partial novelty (Ravì 2017 fusion; SELFY / Jeong & Yoo for the recurrence layer): position the law path and the efficiency; non-inferiority not shown: claim 'level with' only.
P2

IEEE Sensors Letters · data ready, write

Who is tested matters more than the architecture: what drives wearable HAR accuracy under person-disjoint evaluation

Claim
Under a fixed person-disjoint protocol the test person explains ~10x more within-dataset variance than the model; temporal memory is the only architectural component worth several points; channel count predicts when classical models win (30 datasets).
Evidence in hand
variance decomposition (2,460 runs); component contrasts; data-factor regression over 30 datasets; the noise floor (person ~8 points vs memory type ~4 vs seed ~1.7).
Still missing
a 4-page letter; state that the 30-dataset part re-analyses the WHAR Arena paper's published results plus ours; keep the architecture out of the claims.
Risks
correlational data factors (subjects and channels correlated, ρ −0.50); reviewers may ask for other protocols.
P3

IEEE Embedded Systems Letters · L4R5 ready; N6 partial

Deploying published wearable-HAR networks on Cortex-M microcontrollers: faithfulness, cost, and a causal streaming kernel

Claim
Through the vendor compiler only 3 of 14 published HAR networks deploy faithfully on a Cortex-M4; the compiler mis-handles several tensor layouts (found with on-board validation and minimal graphs); a causal model as a streaming C kernel needs 11-21 KB RAM and ~7 % CPU at 50 Hz.
Evidence in hand
deployability table (L4R5, N6); faults and their export-form fixes; per-node profiles (cycles/MAC, conversions); kernel optimization steps (360 → 195 ms); memory breakdown (21 vs 192 KB).
Still missing
the C kernel on the N6's Cortex-M55 (loading via gdb timed out; to debug); a vendor bug report reference if possible. Without a power meter energy is an estimate; a measured figure would strengthen it.
Risks
tied to one tool version (ST Edge AI 4.0.1): frame as a reproducible case study with the export forms released; avoid duplicating P1's accuracy claims (cite P1).

Kept out of the papers

  • The memory-cell and structure explorations of rounds 1–13 (negative): a supplementary table of P1 at most.
  • The sampling-schedule claim (§5k): negative once baselines get resampling; too thin for a paper.
  • The N6 results until our kernel runs there and the compiler faults are reported to ST; then they extend P3.
  • Wearer adaptation (direction 1): moved to its own project, HAR_Lifelong (a sibling project); its phase-0 stop rule was met here (forward-only rules gain at most +1.9 over prototype baselines), so it is not part of these papers.
